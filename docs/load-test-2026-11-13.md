# 실시간 서버 부하 테스트 (1차) — 2026-11-13

우주마을 실시간 서버(`server/`, Socket.IO 4.8.4, Node.js 22)를 **이 작업 환경 안에서** 측정한 결과입니다. 무료 호스팅에 올린 측정이 아니므로, 서버를 배포하면 같은 스크립트로 다시 재서 채널 정원을 정합니다.

## 조건

- 기계: 가상 CPU 2개(Intel Xeon 2.3 GHz), 메모리 8 GB. 서버와 봇이 같은 기계에서 돌았습니다(봇이 CPU를 나눠 씀).
- 네트워크: 같은 기계 안(localhost). 실제 인터넷 지연은 들어가지 않았습니다.
- 봇 동작: 달 착륙지에 들어와 0.1초마다 위치를 보내며 걷고(1.6 m/s), 20~40초에 한 번 채팅합니다.
- 서버: 0.1초마다 바뀐 채널에 스냅숏을 보냅니다. 각 측정은 접속 후 30초(메모리 확인은 10분).
- 지표: 서버의 이벤트 루프 지연(1초마다 p95·p99 중 가장 큰 값), CPU(코어 1개 기준 %), 메모리(RSS), 봇 하나의 왕복 지연과 스냅숏 간격.

## 읽는 법

- 기획서의 통과 기준(루프 지연 p95 20 ms 미만, CPU 70% 미만, 10분 동안 메모리 증가 없음)은 이 기계에서는 100명까지 모두 통과했습니다.
- 정해지는 것은 CPU보다 **보내는 데이터 양**입니다. 한 채널에 모두 넣으면 인원의 제곱으로 늘어서, 100명이 한 채널이면 초당 2.7 MB(정원 30으로 나누면 0.8 MB)입니다. 그래서 채널 정원 30을 유지합니다.
- 무료 호스팅은 CPU가 이 기계보다 훨씬 작게(예: 코어의 일부) 잡히거나 월 전송량 한도가 있을 수 있습니다. 위 숫자는 "이 코드가 이 정도 일을 한다"는 기준이고, **무료 서버에서 30명·100명을 받을 수 있다는 근거는 아닙니다.** 배포할 서버를 정하면 같은 스크립트로 그 서버에서 다시 잽니다.
